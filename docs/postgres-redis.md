# PostgreSQL and Redis

Both are optional and off by default, like MySQL: turn them on in Settings
(PostgreSQL and Redis tabs) or from the command line.

```sh
covo postgres enable            # PostgreSQL 18 on 127.0.0.1:5433
covo postgres password          # connection details, superuser password included
covo db create shop --engine pgsql
covo db list --engine pgsql
covo site add shop --path ~/Sites/shop --database new --engine pgsql
covo laravel api --engine pgsql
covo redis enable               # Redis 8 on 127.0.0.1:6380
```

## PostgreSQL

- Version 18, built by `getcovo/covo-binaries` (`postgres.yml`) from the
  official source tarball, whose SHA-256 published by postgresql.org is
  checked first; Apple Silicon and Intel. Self-contained and relocatable:
  only macOS's own libraries (no ICU, no OpenSSL: the server listens on
  127.0.0.1 only), plus the contrib extensions citext, hstore, pg_trgm,
  unaccent, fuzzystrmatch, btree_gin, btree_gist and uuid-ossp. Each build is
  smoke-tested after being moved (initdb, pg_ctl, psql, pg_dump, extensions).
- Port 5433 by default (5432 is usually Postgres.app's or Homebrew's), the
  first free one otherwise; data in `data/postgres` inside the Covo folder,
  kept when PostgreSQL is turned off and deleted only by `covo uninstall`.
- The `postgres` superuser password is generated by Covo and kept in the
  login keychain (`dev.getcovo.postgres`). It never appears on a command line
  or in an environment variable: initdb reads it from a 0600 file and psql
  from a 0600 `PGPASSFILE`, both removed at once. `scram-sha-256` everywhere.
- A site database gets a role of the same name that owns it, with its own
  password in the keychain; `CONNECT` is revoked from everyone else. Linking
  an existing database connects as `postgres`. Deleting drops the database
  (closing its connections) and the role.
- Adminer (`adminer.localhost`) serves MySQL and PostgreSQL: Covo uses
  Adminer's full build (`adminer-full`) and the same one-time login.
- The major version never changes on its own: data directories of different
  majors are not compatible.

PHP sites connect with `pgsql` (`pg_connect`) on 127.0.0.1 or the socket, and
with PDO `pgsql` **through Covo's Unix socket** (`host=` the folder in
`covo db show <site>`, e.g. `pgsql:host=…/covo/run;port=5433;dbname=shop`):
in the static PHP 8 builds the PDO driver is Swoole's implementation, which
hangs over TCP. New Laravel projects are set up this way (`DB_HOST` is the
socket folder). Covo's own PHP builds with the standard `pdo_pgsql` will lift
this.

## Redis

- Redis 8 (`redis-server` and `redis-cli`, without the optional modules),
  built by `getcovo/covo-binaries` (`redis.yml`) from the official source
  tarball, checked against `github.com/redis/redis-hashes`. Redis 8 is
  licensed RSALv2/SSPLv1/AGPLv3; Covo distributes it under the AGPLv3,
  unmodified.
- One server for every site on 127.0.0.1, port 6380 by default (6379 is
  usually another Redis), also on Covo's Unix socket `run/redis.sock`. No
  password: protected mode on, nothing outside this Mac reaches it. Data is
  saved to `data/redis/dump.rdb` (every hour after a change, or 5 minutes
  after 100 changes).
- New Laravel projects use it (`REDIS_*`, `CACHE_STORE=redis`) when it is on.
  PHP 8 builds include phpredis.

API: `GET /v1/postgres`, `POST /v1/postgres/enable` (`port`),
`POST /v1/postgres/disable`, `GET /v1/postgres/credentials`,
`GET /v1/postgres/databases`; `GET /v1/redis`, `POST /v1/redis/enable`,
`POST /v1/redis/disable`; `POST /v1/sites/{name}/database` takes `engine`;
`POST /v1/sites` takes `database_engine`; `POST /v1/adminer/login` takes
`engine`.
