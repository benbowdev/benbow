# Local domains

Covo only serves reserved, local-only suffixes. Its CA is name-constrained to
them (see [ca.md](ca.md)).

| Suffix | Example | Setup | How names resolve |
|---|---|---|---|
| `.localhost` | `demo.localhost` | none (default) | macOS resolves every `*.localhost` to 127.0.0.1 and ::1 (RFC 6761) |
| `.test` | `demo.covo.test` | `covo domains enable test`, one administrator authorization | `/etc/resolver/test` → Covo's DNS server on 127.0.0.1 |
| `.local` | `studio.local` | MAMP compatibility mode (not available yet) | `/etc/hosts` lines managed by a privileged helper |

The site name is free within these suffixes: `covo site add demo --domain
demo.covo.test`. Other TLDs (`.covo`, `.dev`) and public domains are refused.

## .test

- `covo domains enable test` writes `/etc/resolver/test`:

  ```
  # Generated by Covo. Removed by `covo domains disable` and `covo uninstall`.
  # covo-home: /Users/you/Library/Application Support/covo
  # covo-created-dir: yes
  nameserver 127.0.0.1
  port 53535
  ```

  `/etc` belongs to root, so this takes one administrator authorization through
  the standard macOS dialog (AppleScript `with administrator privileges`: Covo
  never runs sudo and never sees the password). The privileged command is fixed:
  create `/etc/resolver` if needed, copy the staged file, `chmod 0644`, rename
  into place. Nothing else runs as root.
- Covo's DNS server runs as the user, as the launchd agent `dev.getcovo.dns`,
  on 127.0.0.1 only, on the first port free for UDP and TCP from 53535. It
  answers A 127.0.0.1 and AAAA ::1 for every `*.test` name and refuses all
  other names. The port is stored and never changes on its own, since it is
  written in the resolver file.
- The agent runs a copy of the `covo` binary kept in the Covo home, so it does
  not depend on where the CLI was launched from.
- `covo domains disable test` (refused while sites use `.test`) and
  `covo uninstall` remove the file, and `/etc/resolver` too if Covo created it
  and it is empty: one administrator authorization.
- Covo never overwrites or removes a resolver file it did not write for the
  same Covo home (another tool, or another Covo installation).

Verified on the real Mac (2026-10-29, macOS 26.2): one administrator dialog
created `/etc/resolver/test` (root:wheel 0644); `dscacheutil -q host -a name
demo.covo.test` returns 127.0.0.1 and ::1; `curl https://demo.covo.test:8443`
(no `--resolve`) returns 200 with a verified certificate; Safari, Chrome and
Firefox open the site without warnings; the DNS server listens only on
127.0.0.1:53535 (UDP and TCP).

Tests point `COVO_RESOLVER_DIR` at a temporary directory: they run without
administrator rights and never touch `/etc/resolver`, which the e2e inventory
checks.
